# Tasks

Conventions for every task: test first (red, then green), `./gradlew` through the Gradle MCP, `ide diagnostics` on touched files, the build green after each task. A test that characterises behaviour that already works says how to see it fail once (a deliberate temporary break); do that before ticking. "D<n>" refers to `design.md`, scenario names to the delta specs in `specs/`. Spring AI and agent-utils APIs are checked against the real sources (`spring-ai` skill, Gradle MCP `read_dependency_sources`; the agent-utils `-sources.jar` from Maven Central in a fresh empty `/tmp` directory), never memory. Adjuster code lives in `backend/src/main/kotlin/dev/frederikpietzko/springaidemo/backend/adjuster/`, tests next to it under `src/test`. Before starting, refresh this plan against the merged code of earlier changes (the merge hotspots in the design's risks) and note any deviation as a decision.
