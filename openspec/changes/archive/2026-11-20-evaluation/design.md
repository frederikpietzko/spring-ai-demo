# Design

## Context

`CoverageQuestions.answer(question)` returns `CoverageAnswer(text, citations)`; its chat client is private and the answer holds no clause texts. The bean `policyWordingRetriever` (top K 4, filter `corpus == 'policy-wording'`) is the only `VectorStoreDocumentRetriever`. `FraudCheck.assess(claimNumber)` returns `Assessed(FraudAssessment(verdict, evidence = [Evidence(bulletinId, finding)], confidence))` or `Unreadable`; it needs the `ToolCallbackProvider` bean qualified `mcpToolCallbacks` (the MCP client to `core-mcp`) and `SightingBulletinSearch`. The bulletins are `classpath:corpus/sighting-bulletins/SB-10x.md`, with time and place in the file header only. The `test` task scrubs `ANTHROPIC_API_KEY` and `SPRING_AI_*` from every `Test` JVM; `@IntegrationTest` forces fake chat and embedding models; `TestConventionsTest` rejects `@SpringBootTest` outside `@IntegrationTest`. APIs below were verified against the 2.1.0-RC2 sources: both evaluators pass only on the exact judge answer `yes` (ignoring case, after strip); neither returns feedback; `FactCheckingEvaluator` has a protected constructor (use `builder(chatClientBuilder).build()`) and reads only the document list.

## Goals / Non-Goals

**Goals:** a runnable, readable evaluation of the two features with the two built-in evaluators; no effect on `check`.

**Non-Goals:** CI, judge selection, retrieval tuning, a metrics or reporting layer (see proposal).

## Decisions

**D1 Separate source set `evaluation` and task `evaluate`, not a JUnit tag.** A tag in `src/test` would put a `@SpringBootTest` outside `@IntegrationTest` (fails `TestConventionsTest`), join the one shared context, and run in a task whose environment is scrubbed. The source set inherits `test`'s dependencies (`testImplementation` / `testRuntimeOnly`) and main's output; `evaluate` is a `Test` task over its classes. `check` depends on `evaluationClasses` (compiled, never run) and detekt gets `src/evaluation/kotlin` as an extra source (its default sources skip custom source sets), and `config/detekt/detekt.yml` also exempts `**/evaluation/**` from `FunctionNaming`, `MagicNumber` and `TooManyFunctions` (see D10). `evaluate` is `doNotTrackState` and `notCompatibleWithConfigurationCache`: model output must never be up to date or cached, and the key comes from the invoking environment. Rejected: tag plus a second context in `src/test`.

**D2 The credential scrub keeps its deny-by-default shape and skips one task by name:** `tasks.withType<Test>().named { it != "evaluate" }.configureEach { ...existing removals... }`. Rejected: re-adding the key inside `register {}` (depends on configure-action order).

**D3 Own context through a meta-annotation `@RealModelEvaluation`,** in package `...backend.evaluation` (under the base package so `@SpringBootTest` finds `BackendApplication`), declared in this order: `@EnabledIfEnvironmentVariable(named = "ANTHROPIC_API_KEY", matches = ".+", disabledReason = "ANTHROPIC_API_KEY needed")`, `@ExtendWith(OllamaReachable::class)`, `@SpringBootTest(NONE, spring.ai.mcp.client.enabled=false, spring.docker.compose.enabled=false)`, `@Import(EvaluationInfrastructure::class)`. The order matters and gets a code comment: JUnit's `ConditionEvaluator` stops at the first disabled condition and `@ExtendWith` meta-annotations are walked in declaration order, so with the key condition first a run without key never makes the HTTP probe and reports the key reason, not the Ollama one. The real Anthropic model and Ollama embeddings come from the committed `application.yaml` unchanged. `EvaluationInfrastructure` (`@TestConfiguration`, so scanning skips it) holds the Testcontainers `pgvector/pgvector:pg18` with `@ServiceConnection` (copied, not shared: the test output is not on this classpath), the stub core tools and the two evaluator beans. Both skip conditions are JUnit `ExecutionCondition`s that run before the instance (and so the context) exists; an `assumeTrue` inside a test would run after startup ingestion had already called Ollama and failed. `OllamaReachable` enables only on status 200 of `GET <base>/api/tags` with a two-second timeout inside `runCatching` (any exception or other status disables, the reason names the URL); base URL from `SPRING_AI_OLLAMA_BASE_URL`, else `http://localhost:11434`. The condition is kept (rather than "errors without Ollama, like without Docker") because it lets an unattended run and the key-reaches-the-task check end in a clean skip; its unit test is cut to two cases (nothing listens, 200) and the non-200 branch is covered by the same `!= 200` expression, not by a third stub. Only classes annotated `@RealModelEvaluation` are model-backed; `OllamaReachableTest` is plain JUnit and always runs. Rejected: reusing `@IntegrationTest` (fakes, key scrubbed).

**D4 Stub core tools, MCP client off.** `FraudCheck` needs `getClaim`; the real one is a second application with its own database. A stub `@Tool getClaim(claimNumber)` (no `ToolContext` parameter: `MethodToolCallback` accepts that) under the bean name `FraudCheck` qualifies on (`mcpToolCallbacks` at the time of writing; re-check at implementation, `mcp-security` may rename it) returns the `core-mcp` seed values with the field names of `FakeCoreTools`: 4711 `HARBOUR` `2026-11-18T15:00:00Z` class 3; 4712 `OLD_TOWN` `2026-11-16T09:30:00Z` class 5; 4713 `RIVERSIDE` `2026-11-17T18:10:00Z` class 1.

**D5 Judge = the configured Anthropic model, constrained to one word; no `ChatClient.Builder` bean.** In `spring-ai-autoconfigure-model-chat-client` 2.1.0-RC2 `ChatClientAutoConfiguration.chatClientBuilder` is `@Scope("prototype") @ConditionalOnMissingBean`: declaring any `ChatClient.Builder` bean would switch the auto-configured one off, and `CoverageQuestions`, `FraudCheck` and both chat clients would inherit the judge's "reply YES or NO" system prompt (and two declared builders would make injection by type ambiguous). So `EvaluationInfrastructure` declares only the evaluators; each `@Bean` method takes the auto-configured prototype builder (a fresh instance per injection point, so nothing leaks between consumers) and sets the shared judge system text itself: `@Bean fun relevancy(builder: ChatClient.Builder) = RelevancyEvaluator(builder.defaultSystem(JUDGE_SYSTEM))` and `@Bean fun factChecking(builder: ChatClient.Builder) = FactCheckingEvaluator.builder(builder.defaultSystem(JUDGE_SYSTEM)).build()`, with `JUDGE_SYSTEM` a `const val` ("... reply with exactly one word, YES or NO ..."). No temperature override (not verified for this model). Haiku judges Haiku; accepted.

**D6 Relevancy context = the `policyWordingRetriever` bean.** The test retrieves with the same question (same filter, same top K, deterministic embeddings) and passes the clauses as the evaluation data list; `EvaluationRequest(question, clauses, answer.text)`. Rejected: adding clause texts to `CoverageAnswer` (production change that leaks `Document`).

**D7 Fact-check documents = claim facts plus the raw bulletin file.** For every evidence item the documents are one text with the claim's facts (number, place, incident time, class) and the text of `corpus/sighting-bulletins/<id>.md` read through `ClassPathResource` (header included, because the store texts lack time and place, which sit in metadata, and the built-in evaluator reads only text). The claim is `"<id>: <finding>"`: `EvaluationRequest(documents, claim)`. A cited id with no file fails the test. Rejected: bulletin documents from the vector store (no time and place), a custom prompt (the default is enough once the context is complete).

**D8 Expected verdicts: 4711 `FLAGGED`; 4712 and 4713 not `FLAGGED`.** A false accusation is the failure the demo cares about; a careful `INCONCLUSIVE` for a clean claim is acceptable. An `Unreadable` result fails the test.

**D9 Cases and messages.** Coverage questions (one per policy section family): rooftop garden trampled (garden cover), class 5 kaiju damaging a house (Act of Kaiju exclusion), fireworks aimed at the kaiju (provoking exclusion), how much the claimant pays themselves (deductible). Negative controls: relevancy of an off-topic answer ("The harbour opens at 9.") to the garden question must fail; the false finding `SB-102: places the kaiju at the harbour at 15:00` on claim 4711 must fail. Evaluators return no feedback, so every assertion message holds the question or claim, the answer or finding and the bulletin id. Cases are `@ParameterizedTest`s. The power-assert plugin transforms only the `test` compilation, so the suite uses `assertTrue(cond, message)` with explicit messages.

**D10 detekt exemptions for the evaluation sources.** The detekt 2.0.0-alpha.6 default config exempts `FunctionNaming`, `MagicNumber` and `TooManyFunctions` for `**/test/**` etc. by path; `**/evaluation/**` is not covered, yet the suite follows the repo's test style (backticked names, seed numbers in `@ValueSource`, which `MagicNumber` flags because `ignoreAnnotation` is false). Choice: extend `config/detekt/detekt.yml` for these three rules with `excludes` that repeat the default test list and add `'**/evaluation/**'` (a list in a user config replaces the default one). Rejected: camelCase names and named constants in the evaluation sources (breaks the shared test style). `StringLiteralDuplication` is inactive by default and needs nothing.

## Test boundaries

| Behaviour | Boundary | Catches | Misses |
| --- | --- | --- | --- |
| Coverage answers are relevant | `CoverageQuestions` service plus `policyWordingRetriever`, real model, judge `RelevancyEvaluator` | an answer that ignores or contradicts the retrieved wording | judge mistakes (Haiku judges Haiku), nondeterminism |
| Fraud findings are supported | `FraudCheck` service, real model, real vector store, stub `getClaim`, judge `FactCheckingEvaluator` | invented or misread bulletin findings | the real MCP path, bulletins the model never found |
| Verdicts | same context, assertions on `FraudAssessment.verdict` | a false accusation of a clean claim | confidence calibration |
| Skip without Ollama | JUnit condition against a JDK `HttpServer` stub (cases: nothing listens, 200), runs in `evaluate` with no key | wrong URL, timeout, exception handling | non-200 status (same expression), the real Ollama response shape |
| Skip without key, not in `check`, scrub exemption | build wiring, checked by running Gradle (see tasks), not by an automated test | the suite leaking into `check`, a scrubbed key | nothing automated: a Gradle TestKit test was rejected as too heavy for this demo |

The real-model path cannot run in an unattended session (no key). It is verified manually by the owner: `ANTHROPIC_API_KEY=... ./gradlew :backend:evaluate` with Ollama (`nomic-embed-text`) and Docker up.

## Risks / Trade-offs

- Model nondeterminism makes the suite occasionally red. Accepted; four plus three cases keep a rerun cheap, and it is not part of `check`.
- Real-model wiring is unverified in the regular build. Mitigation: the context is smoke-started with a placeholder key and `SPRING_AI_ANTHROPIC_BASE_URL=http://localhost:1` when Ollama is up (tasks), which proves the wiring and ingestion without any request reaching the provider (the first model call fails with a connection error).
- Docker is required (Testcontainers); without it the suite errors rather than skips, which matches `check`.
