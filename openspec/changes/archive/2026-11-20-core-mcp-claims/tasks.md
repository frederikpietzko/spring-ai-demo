# Tasks

Conventions for every task: test first (red, then green) unless the task says it is a build or docs step, Gradle through the Gradle MCP (`mcp__gradle__gradle`, `query_build` / `wait_build`), `ide diagnostics` on touched files, `:core-mcp:detekt` clean, the build green after each task. "D<n>" refers to `design.md`, scenario names to the delta specs (`core-claims-mcp` = CC, `core-mcp-test-harness` = TH, `build-and-quality` = BQ, `schema-migrations` = SM). core-mcp tests need Docker. Test classes live in `core-mcp/src/test/kotlin/dev/frederikpietzko/springaidemo/coremcp/`. Use `kotlin-engineer` policy (sealed results, no `!!`, collection literals), `kotlin-testing` (power-assert, backtick names) and `tdd` (black-box, no mocks). Tests that write data use only the sandbox policy `KP-9000` and their own claims; they never modify claims 4711 to 4713 and never write customers 1 to 3 and 5 or policies `KP-1001` to `KP-1004`. Test classes run in no guaranteed order on one shared database, so exact counts are asserted only over rows no test writes (D2, D6). Committed configuration (`application.yaml`) is read through the `committedProperty(key)` helper in `testsupport` (a `YamlPropertySourceLoader` over `application.yaml`), never through the context's `Environment`, because `RANDOM_PORT` adds `server.port=0` as a test property of higher precedence (spring-boot-test 4.2.0-RC2, `SpringBootTestContextBootstrapper.java:276`). The plan was refreshed against the merged `chat-streaming` and `policy-rag` code on 2026-11-20 (design Context and D14), so no further rebase step is needed; re-read the shared files named in D14 only if another change has landed since.
