# Tasks

Test-first: each task is one red -> green step (behaviour plus its test); the build stays green after each. Boundaries and fakes are in design.md ("Test boundaries"). Use `FakeChatApi`; no mocks.

## 1. Desktop: shared state, visible-press feedback

- [x] 1.1 Move the "is this control usable" rules out of `App` into derived properties of `ChatState` (send, prepare, new conversation, persona, open, confirm claim = newest message holds a card, approve/deny = confirmation pending and not sending), let `main` build the `ChatViewModel` and pass it to `App` (keep the `App(chatApi)` overload for the existing tests). Verify: a new `ChatState` test per rule (scenarios "Send while streaming", "Approve without a confirmation", "Confirm without a claim card") is green and `./gradlew :desktop:test` stays green unchanged.
- [x] 1.2 Move the input text into `ChatState` (`input`, `ChatViewModel.setInput`, `submitInput()` = send the input and clear it; Send and Enter call it), and add `PressFeedback` (`press(target, hold)`, targets `Input`, `Send`, `PrepareClaim`, `ConfirmClaim`, `Approve`, `Deny`, `NewConversation`, `Persona`, `Conversation(id)`) with `Modifier.pressFeedback` (2 dp accent outline, `stateDescription = "pressed"`) on each of those controls; `App` takes the feedback as a parameter with a default. Verify: with `runDesktopComposeUiTest`, "User types and sends" passes unchanged in behaviour, and a control pressed through `PressFeedback.press` shows `StateDescription == "pressed"` for the hold time and not afterwards (scenario "Highlight before the click"); existing `./gradlew :desktop:test` stays green.
