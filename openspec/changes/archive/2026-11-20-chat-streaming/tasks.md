# Tasks

Conventions for every task: test first (red, then green), Gradle through the Gradle MCP, `ide diagnostics` on touched files, the build green after each task. A task that characterises behaviour that already works names how to see it fail once (a sabotage); do that before ticking. "D<n>" refers to `design.md`, scenario names to the delta specs in `specs/`. Backend tests need Docker. Verify every Spring AI or Ktor API against the sources before using it (skill `spring-ai`); design.md names the verified facts.
