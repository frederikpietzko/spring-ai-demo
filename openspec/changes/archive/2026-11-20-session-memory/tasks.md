# Tasks

Conventions for every task: test first (red, then green), `./gradlew` through the Gradle MCP, `ide diagnostics` on touched files, the build green after each task. A test that characterises behaviour that already works says how to see it fail once (a deliberate temporary break); do that before ticking. "D<n>" refers to `design.md`, scenario names to the delta specs in `specs/`. Spring AI APIs are checked against the 2.1.0-RC2 sources, never memory (`spring-ai` skill, Gradle MCP `read_dependency_sources`); anything that differs from `design.md` is descoped to the simplest working variant and reported as a decision. Backend tests live in `backend/src/test/kotlin/dev/frederikpietzko/springaidemo/backend/` (`chat/` for the new ones, `testsupport/` for support code), production code in `.../backend/chat/`. Use a unique conversation id per test (the database is shared).
